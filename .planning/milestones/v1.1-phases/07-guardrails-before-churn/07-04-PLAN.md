<objective>
Exclude the inbox root from the document index the way Scratchpad already is, so
a tree browsed in its own pane stops being index content — across all three
paths that carry the scratchpad exclusion today.

Purpose: on the reference workspace the index carries 11,488 entries of which
~1,906 are inbox rows the documents surface never serves (issue #309). The
scratchpad exclusion already exists at exactly these three call sites
(`scan_vault`, `scan_vault_paths`, the `read_vault_cache` rel-prefix filter);
PERF-06 widens it into a shared non-document-roots list with `inbox/` added,
resolved through the same settings-driven path the inbox scanner uses. The
ROADMAP Note is load-bearing: covering only the full scan and the cache filter
leaves `scan_vault_paths` able to re-inject inbox rows a rescan just pruned, so
all three sites are mandatory.

Output: the shared list and its inbox resolver in `vault.rs`, all three call
sites consuming it, inbox twin tests of the scratchpad exclusion tests, and the
regression watch (inbox/files/content-search suites) proven green. Backend half
of PERF-06; the frontend switcher removal is plan 07-05.
</objective>
