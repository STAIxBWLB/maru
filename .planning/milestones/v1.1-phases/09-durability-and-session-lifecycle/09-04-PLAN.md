## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| webview -> Rust IPC (`write_recovery_copy`) | The frontend supplies workPath, filePath, content, and reason; Rust decides where bytes land on disk |
| Rust -> user workspace filesystem | Writes and prunes files under `<workspace>/.maru/recovery/` |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-09-04-01 | Tampering | recovery file path from `filePath` | high | mitigate | Only the sanitized leaf stem and an allowlisted extension are used; `paths::ensure_within(.maru/recovery)` and `lease.ensure_covered` gate the write; traversal and absolute inputs are tested |
| T-09-04-02 | Tampering | symlinked `.maru/recovery` redirecting writes outside the workspace | medium | mitigate | `symlink_metadata` check refuses a symlinked recovery dir (`recovery_dir_is_symlink`); tested |
| T-09-04-03 | Denial of Service | disk exhaustion via repeated or oversized copies | medium | mitigate | 16 MiB per-copy cap before admission; retention keeps the 100 newest pattern files; pruning never touches non-pattern files and never follows symlinks |
| T-09-04-04 | Information Disclosure | user content in logs | medium | mitigate | The stderr line interpolates only the file label and reason (control characters stripped); content is never logged |
| T-09-04-05 | Repudiation | a lost edit with no trace | low | mitigate | Every write emits the one `[recovery]` line naming file, reason, and kept path |
| T-09-04-06 | Tampering | overwriting an earlier recovery copy | low | mitigate | `write_atomic_create` (persist_noclobber) plus a random 8-hex suffix; same-second double write tested |
| T-09-04-SC | Tampering | package installs | low | accept | No new crates or npm packages (chrono and uuid already direct deps); package legitimacy gate not triggered |
</threat_model>
