# Phase 10 — UI Design Contract

> Visual and interaction contract for Phase 10 (Bundle and Build Hardening). Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Contract nature: regression, not feature.** Milestone v1.1 adds no
user-facing product features (REQUIREMENTS.md) and Phase 10 adds none either.
This phase moves CSS between files (D-01/D-02), drops `script-src blob:` from
the CSP (D-04), and warms mode chunks on idle (D-03). The visual contract is
therefore exactly two claims:

1. Every surface renders **computed-style-identical** after the split (moved
   rules are value-preserving).
2. **No mode shows unstyled content on its first activation** (ROADMAP Phase 10
   criterion 3, the FOUC bar behind the phase's `UI hint: yes`).

Every token below is the EXISTING foundation value. This phase introduces no
new visual values; it relocates existing ones.

### Styling source of truth (unchanged by this phase)

  split, not moved, not edited.
- `src/styles.css` - the single color-definition site (hanji-ink-seal palette,
  including the first-paint scheme fallback at the file head) plus shell chrome
  and shared rules. After D-01 it shrinks to base + shell + shared rules.
  Invariants that NEVER leave it: the `:root` token blocks, the head-of-file
  `prefers-color-scheme` first-paint fallback, `.mode-loading` /
  `.editor-loading` (styles.css:4024-4035), and `.sr-only` (documented
  cross-file dependency at graph.css:529-530).

  the top of the mode's top-level pane component (the
  graph.css / diagram.css / settings.css / meetingSourceWorkbench.css
  precedent), riding the mode's lazy chunk via Vite's default
  `cssCodeSplit: true` (no vite.config.ts change).

## Typography

New type declared by this phase: **none**. Moved rules keep their existing
`var(--type-*)` / `var(--read-*)` tokens verbatim.

Guard note for the split: `check-type-tokens` greps only `src/styles.css`
(Makefile:200-204). Moving a raw-px rule into a per-mode file to escape the
gate is a forbidden guard-weakening change (RESEARCH pitfall 10).
`src/styles.css` is currently clean of raw px `font-size` (only `0.9em` and
`0` relative values exist); keep it that way.

## UI Considerations

Applicable state considerations resolved: 2 covered, 2 backstop, 0 unresolved.
Everything below is judged against one bar: the split is value-preserving, so
each state either renders identically post-split or the split is wrong.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| loading (first activation - FOUC) | all 18 mode surfaces via ModeSurfaceHost | ✅ covered | First activation renders the `.mode-loading` entry-stylesheet fallback until the mode chunk (JS+CSS) arrives; D-03 idle preload warms chunks before first click; no unstyled frame (ROADMAP criterion 3) |
| loading (chunk failure) | mode surfaces | ✅ covered | Idle-preload failure degrades gracefully to a normal lazy load (RESEARCH); activation-time chunk failure is pre-existing behavior unchanged by a file move; no ErrorBoundary exists in src today and adding one is out of scope |
| populated (visual parity) | every moved rule | 🧪 backstop | Every mode renders computed-style-identical after the split; verified by the new first-activation e2e computed-style assertion (`e2e/first-activation-styles.spec.ts`, Wave 0 gap) |
| cascade order (split-specific) | rules that today resolve by source order | 🧪 backstop | Lazy CSS loads after the entry stylesheet, so a duplicated selector whose two definitions land in different files can flip its winner (`.empty-state` is defined TWICE in styles.css at :3608 and :24063); the D-02 boundary review must give every duplicated selector one home, and the e2e parity assertion must cover at least one mode exercising each duplicated selector |
| empty / error / partial / overflow / zero-one-many / long-text | all | dismissed | CSS file placement changes no rule content; these states' rendering is unchanged by construction (values move verbatim), so raising them would re-ask questions the refactor cannot change |

Notes for the planner and executor:

- **Dark-scheme parity (`default`):** the e2e assertion must run under both
  `prefers-color-scheme` values (`colorScheme: "light"` and `"dark"` in
  Playwright). The dark fallback is the first-paint path where a FOUC would
  actually show; RESEARCH left the scheme unspecified and both is one line.
- `check-select-chrome.mjs` walks all `src/**/*.css`, so per-mode files stay
  inside the background-shorthand guard - do not reintroduce shorthands that
  clobber entry-defined backgrounds (RESEARCH pitfall 5).
- Shared utilities referenced by lazy CSS (`.sr-only`, `.mode-loading`) stay
  in styles.css; the D-02 boundary review applies that rule to every shared
  utility a per-mode file references.
