<objective>
Convert the six named process-global locks from poison-bricking to
poison-recovering, each with its own recorded justification, so a panic under any
of them leaves the feature usable on the next call instead of returning a
poisoned error until app restart.

Purpose: all six are unit mutexes (`Mutex<()>`) whose guarded state lives on disk
and is re-read after acquisition — the in-memory `()` carries no invariant, which
is why recovery is safe. But REQUIREMENTS.md forbids blanket recovery precisely
because poisoning marks a potentially violated invariant, so each lock needs its
own justification (D-03) and the recovery must not leak to locks outside the six.
Phases 8-10's churn will stress these locks; PERF-03 lands the safety net first.

Output: a new `lock_recovery` module with the shared recovery helper and its
tests, recovery wired into all six locks across five files, per-lock D-03
justification comments, one eprintln warn line per recovery (D-01), and the six
retired poison error strings gone from the lock files.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Panic path -> process-global locks | A panic while holding a lock currently bricks the feature; recovery trades that availability loss for continued operation |
| Recovery helper -> any future lock | A blanket recovery applied to invariant-bearing in-memory state would convert a loud panic into silent corruption |

| T-7-05 | Denial of service | Poisoned lock bricks skills/jobs/dot-sync/binder/terminal until app restart | medium | mitigate | This plan — poison recovery with one warn line per recovery (D-01), verified per lock by `cargo test --lib` |
| T-7-06 | Information disclosure | Recovery warn line leaks path or user data to stderr | low | accept | The warn line carries only the module tag and lock name — no paths, no payloads; stderr of a local desktop app is a developer surface, not user-visible |

No package installs — T-7-SC not applicable. ASVS L1; no auth/session surface in this plan's scope.
