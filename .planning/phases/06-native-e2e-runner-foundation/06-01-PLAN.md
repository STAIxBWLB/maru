<objective>
Stand up the thinnest end-to-end native-runner path and use it to open the CI-viability
spike. One command builds the real app with the runner feature on, points it at a
throwaway fixture workspace, launches it under WebdriverIO's embedded provider, and
asserts one thing about the real WKWebView DOM. The same slice then runs on a hosted
macOS runner so D-02's stop condition can fire on the earliest possible evidence.

Purpose: TEST-01's whole premise is that a runner drives the real application. Everything
later in this phase (PTY assertions, IME sub-spike, ship-isolation guard, the recorded
verdict) is an expansion of this one path, and none of it is worth writing until the path
itself is proven to exist. Implements D-01, D-02 (opening move), D-09, D-10 (declaration
half), D-11, D-12, D-13 surface 1, D-15 (directory), and RESEARCH Pitfalls 1, 2, 7, 8.

Output: the `native-e2e` cargo feature, the fail-closed isolation override, the
`e2e-native/` tree with its config, fixture helper and first spec, the
`make test-e2e-native` target, the hosted-macOS spike workflow, and the spike log.

This plan does NOT presuppose the spike's outcome. Its deliverables are identical in both
branches of D-01; only what `docs/native-e2e.md` records differs.
</objective>

<assumption_delta_decision>
The detector fired `pluralization` on this phase's scope. The real transition it names is
this: before Phase 6, "the e2e suite" in this repository meant exactly one thing -
Playwright, Chromium, plain Vite, mocked IPC. This phase introduces a second suite with a
different runner and a materially different premise.

- **Primary noun:** the *test-runner tree*. The generalized identity is "a runner tree,"
  of which `e2e/` (Playwright, mocked IPC) and `e2e-native/` (WebdriverIO, real backend)
  are two variants.
- **Decision:** `add-alongside`. D-15 locks `e2e/` as Playwright-only and puts the native
  runner in its own tree with its own config, tsconfig project, ESLint block and make
  target. Promoting a shared `e2e` umbrella now would hide the one thing that most matters
  when a spec fails: which premise it was running under. A mocked-IPC failure and a real
  WKWebView failure are not the same kind of news.
- **Accepted debt:** `pnpm test:e2e` and `make test-e2e` keep meaning "the Playwright
  one," so a green `make test-e2e` can be misread as full e2e coverage. `docs/native-e2e.md`
  (plan 06-05) must state which target covers which premise.
- **What would force a promote:** a third runner tree, or the first shared helper both
  trees need (fixture seeding, selector conventions, reporting). At that point a neutral
  umbrella target that fans out to every registered tree becomes the right primary.
- **Suggested (not planned) invariant test:** an assertion that every top-level runner tree
  is registered in both `tsconfig.json` `references` and `eslint.config.js` `files`. It
  goes red the moment a future phase adds a third tree without wiring it. Not tasked -
  D-14 keeps this phase to the runner skeleton and the four representative tests.
</assumption_delta_decision>
