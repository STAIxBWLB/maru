## Pattern Assignments

### `Makefile` (config/utility, batch) - new `coverage` target

**Analog:** `Makefile` lines 233-266 (`test-e2e-native` comment block + `verify-integration`), same file.

**Convention pattern** (Makefile:233-241, `test-e2e-native`):
```makefile
# Deliberately NOT part of `verify`: it builds and launches a real macOS
# .app under WebDriver and cannot be hermetic (TEST-01, D-15) - the same
# reason verify-integration sits outside verify. It IS part of
# `release-preflight` (D-03, wired in 06-05), which is human-run on macOS.
# This target's frontend build is VITE_NATIVE_E2E=1
# and is deliberately not shippable - re-run `pnpm build:frontend` before
# inspecting a production artifact.
.PHONY: test-e2e-native
test-e2e-native: node_modules ## Native WebDriver e2e against the real app (macOS; builds with the native-e2e feature)
	$(PNPM) build:frontend:native-e2e
	...
```

**Core CRUD-adjacent pattern** (Makefile:262-266, `verify-integration` - same "why excluded" comment shape, uses `$(TAURI_DIR)`/`$(CARGO)` vars):
```makefile
# Deliberately NOT part of `verify`: this depends on which AI CLIs are installed
# and whether their tokens are live, and a merge gate that fails on an expired
# token is a gate people learn to bypass. Run it when touching provider.rs,
# skill_host/dispatch.rs, agent_host/status.rs or terminal/mod.rs.
.PHONY: verify-integration
verify-integration: $(ICON_PATH) ## Smoke the real installed AI CLIs (availability, auth, usage, permission parsing). Uninstalled CLIs are skipped. MARU_CLI_SMOKE_ROUNDTRIP=1 adds one live prompt per authenticated backend.
	cd $(TAURI_DIR) && MARU_CLI_SMOKE=1 \
		$(CARGO) test --lib cli_backends_real_smoke -- --ignored --nocapture --test-threads=1
```

**Variables available for reuse** (Makefile:16-20,25-26):
```makefile
PNPM       ?= pnpm
CARGO      ?= cargo
TAURI_DIR  := src-tauri
ICON_PATH  := $(TAURI_DIR)/icons/icon.png
```

**What to copy for `coverage`:** the leading comment block naming the requirement ID (TEST-02) and the decision IDs (D-01/D-04) it satisfies, `.PHONY:` + `$(ICON_PATH)` prerequisite (matches `test-rust`/`verify-integration`, not `node_modules`-only), and the `cd $(TAURI_DIR) && $(CARGO) ...` idiom for the Rust half. `verify` itself lives at Makefile:375-376 - do not add `coverage` to that prerequisite list (D-01).

### `.github/workflows/ci.yml` (config, event-driven) - new `coverage` job

**Analog:** `ci.yml` `verify` job (lines 101-186) and `e2e` job (lines 189-230), same file.

**Imports/setup pattern** (ci.yml:109-176, `verify` job - checkout, pnpm/node/rust setup, Linux Tauri deps):
```yaml
      - name: Checkout
        uses: actions/checkout@v5
      - name: Setup pnpm
        uses: pnpm/action-setup@v6
        with:
          version: 9.15.0
      - name: Setup Node
        uses: actions/setup-node@v5
        with:
          node-version: 22.22.3
          cache: pnpm
      - name: Setup Rust
        uses: dtolnay/rust-toolchain@stable
      - name: Cache Rust build
        uses: Swatinem/rust-cache@v2
        with:
          workspaces: src-tauri -> target
          shared-key: ubuntu-22.04-validation
      - name: Install Linux Tauri dependencies
        run: |
          sudo apt-get update
          sudo apt-get install -y \
            libwebkit2gtk-4.1-dev \
            libxdo-dev \
            libssl-dev \
            libayatana-appindicator3-dev \
            librsvg2-dev
      - name: Install frontend dependencies
        run: pnpm install --frozen-lockfile
```
For the coverage job's Rust setup, add `with: { components: llvm-tools }` to the `dtolnay/rust-toolchain@stable` step (not present in `verify`'s copy - `cargo-llvm-cov` needs it, RESEARCH.md Pitfall 4) and add a `taiki-e/install-action@cargo-llvm-cov` step after it.

**Job-gating pattern** (ci.yml:36-104, `decision` + `verify`'s `needs: decision` / `if: needs.decision.outputs.run_full == 'true'`): do NOT copy this for the coverage job - RESEARCH.md Pattern 2 is explicit that coverage must gate on `if: github.event_name == 'push'` alone, independent of the `decision` dedup job, since every main push (even one already PR-validated) is a legitimate point to refresh the baseline.

**Artifact upload pattern** (ci.yml:221-229, `e2e` job's "Upload e2e artifacts on failure"):
```yaml
      - name: Upload e2e artifacts on failure
        if: failure()
        uses: actions/upload-artifact@v4
        with:
          name: playwright-report
          path: |
            playwright-report/
            test-results/
          retention-days: 7
```
Copy this shape for the coverage job's artifact step but drop `if: failure()` (coverage should upload on success too, since it is non-gating evidence, not a failure diagnostic) and point `path:` at `coverage/`, `retention-days: 30` per RESEARCH.md's Pattern 2 example.
