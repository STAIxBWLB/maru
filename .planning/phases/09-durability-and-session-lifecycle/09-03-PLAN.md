<objective>
Route Cmd+Q into the one window-close guard (D-03) and settle research open
question 1 (assumption A1) early, before the quit flush work in plan 09-08 builds on
it.

Purpose: `RunEvent::ExitRequested` fires only for last-window-destroyed or
`AppHandle::exit()`; the macOS native Quit item (`PredefinedMenuItem::quit`) calls
`NSApplication terminate:` and bypasses both the webview confirm and any flush
(research Pitfall 2, verified in tauri-runtime-wry 2.10.1 source). Replacing that
item with a Maru `command_item` routes Cmd+Q through the existing generic
menu-command path into `requestWindowClose()`, the same code the red close button
reaches. No new `#[tauri::command]` is added, so the 382-command isolation evidence
is untouched.

Output: macOS App submenu with an `app.quit` item, one App.tsx menu case, a native
spec proving the route, the docs checklist item, and a human check of the real
keypress.
</objective>
